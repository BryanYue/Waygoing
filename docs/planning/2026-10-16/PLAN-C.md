## 2. 产品关系与责任边界

| 层 | 负责的行为 | 第一阶段处理方式 |
| --- | --- | --- |
| DeepSeek 宿主 | 模型请求、工具循环、上下文与执行轨迹 | 复用所选版本；记录实际模型和配置，不把宿主品牌等同于模型服务或计费来源 |
| LifeOS 接入层 | 将受限业务操作提供给模型，映射输入、结果和错误 | 候选为自有薄插件调用本地 HTTP API；宿主依赖集中于这一层 |
| LifeOS 业务层 | 稳定实体身份、计划／事实／推断、字段权限、版本、笔记及领域规则 | 继续作为业务真相来源；不让插件或会话历史维护第二份可独立写入的个人账本 |
| LifeOS 界面与用户 | 查看原始记录、修改内容、决定是否落实建议 | 先复用现有能力；不假定任意 agent 建议已经有自动转换为计划的入口 |
| Waygoing 自研内核 | 用户逐步掌握和实现通用运行机制 | 沿用 B；具备所需能力后再接同一业务接口，不从第一课做完整平台 |

LifeOS 自身的业务插件机制与 DeepSeek 的运行时插件是不同层。首阶段不同时扩展两套插件框架；已有 API 足够时直接复用。业务语义应可独立检查，宿主适配器可以重写。MCP 是将来跨宿主提供工具的选项，不自动保证权限、恢复或 UI 可移植。

非目标：八领域同时智能化、完整界面重做、私人数据迁移、真实 Vault／设备／云同步、自动提醒、无人值守运行、金融执行、外部消息，以及把 Plan A 全部迁入 Waygoing。它们不作为首阶段通过条件。

## 3. 第一阶段要回答的问题

样板任务：给定一组学习目标、技术阅读记录、用户实际完成的实验及尚未完成的事项，请 agent 总结“有哪些证据支持当前进度、哪里仍不确定、下一次值得做哪个小实验”，并引用具体来源。

第一阶段先回答两个问题：现有接口能否完成受限读写；结果是否足够准确、清楚，值得进入后续真实试用。**合成场景通过不能证明用户形成习惯、学习进步或获得长期收益。**

首组候选材料使用公开／合成内容，可包含：一份英文技术阅读记录、一项 harness 学习目标、一个成功实验、一个失败实验、一项只有计划没有完成事实的任务，以及关联多个目标的同一次阅读。数量由覆盖这些行为所需的最小集合决定，不扩成大型数据集。

输出至少能区分：

- 已观察到的事实，带记录 ID／版本和来源；材料原文与 agent 解释分开。
- 证据缺口或冲突；没有记录不推定用户没有做过或没有能力。
- 下一次建议、理由和所依赖的证据；建议仍是推断，不伪装成人工采纳或完成事实。

## 4. 可复用接口与尚未解决的限制

当前 LifeOS 的 `GET /api/agent/entities` 按 `agentModules`／`agentScope` 返回获准数据；`POST /api/agent/suggestions` 使用 AI capability 写入。`Store` 限制其只能创建新的 `draft inference`，拒绝修改已有记录和直接写成计划／事实。Bearer 请求也不能访问普通人工 API。[接口源码](https://github.com/BryanYue/life-os/blob/d2607cef1c9ef96d10392aa77243673a42ad54ae/src/server.ts#L518)、[数据层限制](https://github.com/BryanYue/life-os/blob/d2607cef1c9ef96d10392aa77243673a42ad54ae/src/store.ts#L628)

候选工具仅围绕两项能力：读取学习证据、保存复盘建议；工具名和最终 JSON Schema 在实现前依据真实 API 确定。读取结果先按最小模块／字段授权，再由适配器选择当前任务需要的材料。现有 GET 并不是已经实现按日期、分页或任意查询的检索 API，不能在计划中虚构这些能力。

专用学习统计／报告并未通过这两个 Agent 入口完整暴露。首阶段不让模型代替业务代码计算权威统计；必要的合成预期由既有规则和人工核对提供。若任务确需新增受限报告入口，应先说明字段、权限和业务必要性，不能偷用人工会话 token、开放整个服务或直接读写 SQLite 绕过限制。

重复写入与响应丢失也不能直接沿用其他业务命令的幂等承诺：当前接口尚未完成这项端到端核验。第一阶段先禁止盲目自动重放建议提交；结果未知时记录请求与状态，读取／核对可识别记录后再决定。若要承诺可靠自动重试，需另有经过验证的身份与幂等契约。

DeepSeek 的插件入口和 MCP 客户端可供接入，MCP 桥接源码会发现、注册并转发外部工具；这些证据只支持接点存在，不证明 LifeOS 插件已运行。[插件入口](../../../reference-harness/deepseek-harness/docs/cordis-tutorial/01-first-plugin.zh.md)、[MCP 实现](../../../reference-harness/deepseek-harness/packages/mcp/mcp-client/src/tools.ts)

## 5. 第一阶段的执行顺序（未来获准实施后）

| 步骤 | 要做什么 | 完成证据与下一步条件 |
| --- | --- | --- |
| C1.0：固定样板与环境 | 选材料和问题；核对 LifeOS／DeepSeek 版本、运行命令与兼容工具链；建立隔离的合成数据根和最小授权；确定适配器自有目录、模型服务及实验预算 | 材料清单、预期事实与禁止推断、版本／环境记录；不复制真实数据。未确定付费调用条件时可继续离线工作 |
| C1.1：验证 API 与薄适配器 | 先用确定性请求检查读取、权限拒绝和建议写入；再把相同行为接为 DeepSeek 工具 | 实际 HTTP／工具输入输出与数据库前后差异；能看到工具失败；没有用模型掩盖接口错误 |
| C1.2：完成一次受控模型任务 | 用选定材料完成复盘和建议，记录输入范围、工具轨迹、结果、错误与可得 usage；先查看回答，再按试验范围保存建议草稿 | 每个事实可追到材料；建议与事实分开；LifeOS 中可找到实际保存的记录，文字“已保存”不能代替写入证据 |
| C1.3：检查关键反例与重开 | 对下面的必要边界执行最小检查；重开 LifeOS／宿主后核对业务记录，验证结果未知时不会盲目重复提交 | 正常流程和反例均有结果；重开后记录可查，不因此宣称有后台调度、自动任务恢复或 exactly-once |
| C1.4：阶段评估 | 用户查看输出是否易理解、是否愿意据此安排下一次学习；比较直接查看同一批记录所需的整理与纠正 | 分别给出“技术接入”“合成任务质量”“用户对试用的意愿”；决定是否进入有限真实试用、调整交互或暂缓 C |

模型使用、时间、请求／输出和费用上限在 C1.0 确定后，重试也计入同一范围。没有授权和预算不执行付费调用。公开／合成材料先行；后续真实材料必须明确哪些内容进入模型服务，本机保存不等于模型上下文只在本机。

## 6. 候选完成判据与必要反例

以下用于形成后续实施验收；不修改 LifeOS 既有正式契约，不把本轮尚未运行的场景标为通过。

| 场景 | 需要观察到的行为 |
| --- | --- |
| 正常读取和复盘 | 返回材料支持的结论及来源；建议明确标为推断；只使用当前任务获准字段 |
| 只有计划、缺少记录或相互冲突 | 不声称已完成、不虚构学习分钟；指出缺口／冲突，仍可完成有依据的部分 |
| 一次阅读关联多个目标 | 不把多个目标的覆盖时长相加成总投入；无法取得权威统计时说明限制 |
| 越权、错误参数、停用模块或服务不可用 | 工具返回可识别失败；无未获准业务变化；不回退到人工 API、原始文件或更大权限 |
| 保存建议 | 只创建允许的新推断草稿；不能覆盖原文、修改事实或把建议直接转为已采纳计划 |
| 提交中断／响应丢失／重试 | 明确区分未发出、已确认成功、结果未知；未知时先核对，避免盲目再次写入 |
| 取消或达到实验上限 | 停止后续调用，保留已发生动作及状态；不声称撤销已经完成的写入 |
| 重开与记录追查 | 保存的业务记录仍由 LifeOS 读取；会话里的文本不能作为唯一完成凭据 |

先用确定性调用验证业务约束，再用少量真实模型调用验证理解和工具使用；不对每个拒绝场景反复消耗模型额度。若稳定场景仍需大量人工改错，记录原因并调整当前问题，不增加多 agent、提示词分支或整库重写来掩盖失败。

合成阶段完成后，真实使用价值仍未验收。后续可在明确选定的低敏学习材料上试用，记录是否重复使用、采纳了什么、纠正了什么、是否比手动整理省力；不预设学习效果分数或固定 ROI。

## 8. 云端准备、停止条件与接续

Waygoing 云环境当前先用于源码研究、计划维护及将来的隔离开发，配置入口见 [参考仓与云环境](../../REFERENCE-HARNESS.md)。首次环境准备只需主仓与四个参考仓的源码；C1 真正实施时再按需要准备 LifeOS 源码、Node／包管理器和合成数据。LifeOS 不作为第五个 harness 子模块加入 Waygoing。

候选先在 Mac 的隔离合成数据环境完成 C1，以便复用本地业务层和界面；云端可承担源码检查及合成测试，但它的 `127.0.0.1` 不是 Mac 的 LifeOS 服务，不把本机 Vault、数据库或既有配置上传成环境模板，也不为此暴露本地端口。

需要暂停对应步骤的情况：关键权限或业务契约必须改变、数据／模型预算未明确、版本不兼容、无法核对提交结果、真实材料超出批准范围。普通实现选择和授权内修复不额外增加审批；用户已批准实施后按实际边界连续推进。停用适配器并撤销专用试验授权即可退出试验，保留证据与合成数据；不修改或删除原业务数据，不以覆盖原库作回滚。

本轮成果为本计划及三路线入口更新；C1.0–C1.4 均未执行，无运行中的任务或待等待的模型调用。用户随后已确认云环境配置完成，并授权文档提交推送；该确认不代表 C1 已执行。下一步处理用户对候选细节的修订；用户若继续 B 学习，直接从其首单元设计进入，不要求先完成 C。
