## 批准身份与保护集

任务负责人沿已有授权，在启动 Claude 的环境或受控的现有设置 `env` 中提供 `ORACLE_GUARD_APPROVALS`；值是 JSON 数组，数组每项为：

```json
{"root":"/absolute/worktree","baseline":"<完整的已批准 commit ID>","manifest":"docs/internal/orchestrator/<task>/oracle-manifest.txt"}
```

这是输入格式，尖括号必须换成实际值。root 是执行 worktree 的绝对仓库根目录；baseline 必须是完整 commit ID，不能是 HEAD、分支名或临时猜的提交；manifest 是该 commit 内的相对路径。注册可含多个任务或 worktree，但只登记明确批准的范围。工作树、索引、分支移动和历史台账均不构成授权来源；不自动迁移旧计划。未登记意味着项目级入口保护未启用，正式要求仍受工作规则约束。

清单从批准 commit 的 Git 对象读取。每行一个规范仓内相对路径、目录或 glob，空行和 `#` 注释忽略；glob 按整条路径匹配，`*` 可跨目录，**只展开该基线已有文件**。未命中、空清单、不可读基线以及链接/子模块判据均报错，不能静默缩小保护集。清单自身自动纳入，delta 及正式验收文件须在清单中列出；尚未批准的新测试不会因为匹配目录、暂存或提交而被冻结。

在实际执行会话检查 `bash ~/.claude/hooks/oracle-guard.sh --list`：输出每项 root、baseline、manifest、manifest_sha256 和具体 paths。此命令与入口判断共用同一解析逻辑；`disabled: true` 或当前任务未列出时，不能报告该任务的入口保护有效。需确认 hook 进程采用同一组登记；不要只在一次 Bash 调用中临时赋值后把它当成会话已接入。

沙箱和验收都消费这里导出的具体路径，不各自重读工作区清单或另猜 glob。登记信息与真实覆盖结果记在现有任务 PROGRESS，并给出授权来源；不必保存一份重复清单。受控设置是否已被运行会话加载要实际核对，不假定热加载。授权修订替换对应登记，核对旧新基线的判据差异仅包含获准部分；其他项目与其他有效批准保持原状。

## 沙箱接线与证据

启用是独立的机器/项目配置变更，本次未启用。配置按适用项目合并；下面只展示关键开关：

```json
{"sandbox":{"enabled":true,"allowUnsandboxedCommands":false,"autoAllowBashIfSandboxed":true}}
```

在 `sandbox.filesystem.denyWrite` 中列入实际批准集对应的绝对文件路径，以及需要保护的协议、hooks 和设置位置。使用具体路径，避免以通配规则冻结未来任务的草稿。清单登记不会自动修改沙箱；由获授权负责人完成设置。设置路径语义、覆盖与例外以当前会话的有效配置为准。

`allowUnsandboxedCommands: false` 关闭通用沙箱外重试，**不覆盖 excludedCommands**。排除命令在沙箱外运行，不受 denyWrite 约束；默认不添加排除项，确需例外则在任务约定记录用途及可触达判据。不能因工具兼容性失败就自动排除整类命令。

验证分开记录，不能互相替代：

1. **配置覆盖**：核对会话实际采用的沙箱模式、有效 denyWrite、路径解析与排除命令，逐项对上导出的具体保护集。漏项或查不清记为未覆盖/未确认。
2. **机制探针**：只对明确供测试使用、已确认普通用户可写的临时探针做一次沙箱试写，并核对确为沙箱拒绝。专门列入 denyWrite 的探针失败，只证明探针路径被拒，不能代替上一步；普通权限错误、目录不存在等也不是沙箱证据。不试写真实判据，不覆盖既有探针的他人改动。
3. **实际模式**：任务记录同时写“需要哪些保护层”和“已确认哪些层”。必需层未启用或未确认时，只暂停依赖它的执行；DEBT 不能自动降级要求。若已有授权明确允许较轻模式，则沿该模式推进并如实报告，无需重复批准。

不为每个判据制造探针，不默认建立已跟踪的 `.deny-probe`，也不以最终文件相等推断中途从未被修改。配置变化、执行目录变化或新证据影响覆盖时，重核受影响部分即可。

## 验收与错误处理

验收使用上述导出的非空 paths 及对应 baseline，按参数数组或正确引用传给 Git，避免把文件名当作 shell 或 Git 通配表达式：

```text
git --literal-pathspecs diff <baseline> -- <paths...>
git --literal-pathspecs status --porcelain -- <paths...>
```

两条命令须成功且输出为空；它们检查工作区与暂存状态，不能只比提交。偏离使相应验收及受影响结果不可用；不自动还原共享文件。多个有效登记分别按其基线检查，不能拼成一个未经批准的新基线。

hook 输入、登记、Git 读取及解释器异常均返回阻断码 2；只有确认范围外才放行。未登记是明确的未启用状态，不是通过检查。宿主未调用 hook、关闭 hook 或在外部终止 hook 不由脚本自行保证；Bash 由沙箱负责，MCP 等写入由各自权限约束，不能用 hook 的测试结果代替这些边界。

`ORACLE_GUARD_OFF=1` 仍只识别 hook 继承的实际环境，用于已获授权的维护；文字里提到开关不算。它是维护开关，不是授权证明，完成后由负责人核对恢复；本次修改未开启此开关。

## Claude 更新 dispatch skill 时的接口

- 草稿阶段可写 delta 和清单；批准文本已有则复用授权，不按 git add/commit 产生批准。
- 明确批准的基线提交后登记 root + baseline + manifest，核对 `--list` 与任务一致；不能猜旧基线或自动批准新判据。
- 将导出的具体 paths 接入沙箱配置与验收；分别记录配置覆盖、探针结果及实际保护层，删除“探针被拒即全保护生效”的推断。
- 删除默认 `.deny-probe` 跟踪和 KNOWN-GAP 自动降级；必需保障不足只暂停依赖工作，已有较轻模式继续。
- 合法变更沿已有授权同步登记及引用，确认获准差异，不重设全部验收、不扩大写面。
