# 独立方案审查

审查日期：2026-10-15。审查者为未参与该方案起草的独立实例。本报告仅审查候选方案，不修改规则源文件，不代表宿主权限、会话关闭或新运行时已实现。

## 总体判断

**方案方向成立，可以据此起草工具中立的新规格；不需要为下述修正再取得用户决定。** 它已正确把“编排模式中的协调者”与“一切任务的主代理”分开，保留简单任务直接处理，落实独立测试作者及独立审查，并且没有把 Codex、Claude、跨产品插件、固定 lane 层级或额外收官席变成必经层。

目前仍有三项在正式候选成文前必须补齐的机制边界：正式判据与监视配置的关系、要求与证据的最小追溯、外部动作在崩溃前后的持久记录。这些不阻止继续起草，属于起草者可以在本次授权内解决的必要修正；若在替代正文里仍缺失，则不宜按完整可恢复规格采用。

“通用”应表现为统一责任、授权、候选身份、证据与恢复原则；不宜表现为所有研究、文档和简单事务都强制复制代码项目的席位和工件。现方案基本选对方向，正式正文需继续守住这一点。

## 阻断采用的问题

### IPR-B1：监视集不能承接并弱化已正式确认的选择规则和阈值

- **定位**：plan-for-review.md 第 21 行（设计 7），关联第 22—24 行。
- **触发条件**：已有正式验收阈值、排除规则、测试选择或证据生成约束位于构建配置或检查脚本中；执行者将该文件归入“监视集”，据“触及不自动等于缺陷”理解为只需记录，允许改变实际门槛后继续验收。
- **影响**：正文虽然宣称保护正式判据，却没有明确“内容的正式性质”优先于“文件属于哪个集合”。W06 明确保护的既有阈值可能因此降为待观察配置；仅保护测试断言仍可能漏掉跳过、缩小覆盖或降低门槛。
- **证据**：W06 保护既有验收/golden/阈值，禁止缩小分母和跳过必需场景；v2.9 §0 将必需行为、场景与覆盖固定，命令可调不得削减它们。旧修订单复核 6-A 同时要求保护验收选择/预期/阈值/证据生成控制，不能只按文件类别判断。
- **最小修正**：明确两层关系：正式约束无论位于测试、配置、脚本还是外部资源都受保护；监视集用于发现“可能影响验收”的变化并进行独立定性。语义等价维护可授权内继续，未获准改变正式判据则阻断受影响验收。无需把所有配置文件永久设为不可写，也无需每次触及都问用户。

### IPR-B2：凭证字段不足以替代要求—检查—结果的追溯

- **定位**：第 19、22、23、29 行（设计 5、8、9、15）。
- **触发条件**：新正文替代 v2.9，任务只记录目标、验收和若干真实执行凭证，但没有记录哪些必需场景由哪些检查或其他证据覆盖。协调者调整检查命令或拆分候选后，真实的绿色结果来自一个较窄集合。
- **影响**：证据确实执行过、版本也正确，仍不能说明已确认的覆盖全部满足。独立确认席只能重新猜测对应关系，且容易把“存在测试/命令成功”误认为“完成目标”。
- **证据**：v2.9 §0 要求不变量给检查命令或允许例外，并分开冻结的必需覆盖与可调命令；旧修订单复核 0-A/0-B/2-B、2-I 均明确保留需求/场景/检查/证据追溯。现方案第 23 行只列执行身份与结果字段，没有明确要求这条最小关系。
- **最小修正**：按任务实际需要记录“正式要求或必需场景 → 适用检查/观察方法 → 候选/执行凭证 → 独立结论及未覆盖项”。小任务可以一两句完成，编排任务沿用现有任务入口，不强制新文件、固定 schema 或逐条机器证明。自动测试、人工检查、设备观察、来源核验都可成为适用方法。命令调整需说明必需覆盖为何仍保持；若无法证明，相关项保持未验证。

### IPR-B3：外部动作必须覆盖“已发出但尚未写回执时崩溃”的窗口

- **定位**：第 26—27 行（设计 12、13）。
- **触发条件**：发送、预约、付款、发布等动作已发到外部系统，进程在写下请求或回执前中断。新实例恢复时只看到本地最后一个“未执行”检查点，外部平台又不提供立即可用的查询或幂等键。
- **影响**：现有“结果未知先查询、未证实可安全重试前不重复”原则正确，但后继实例可能根本不知道存在未知动作，重放任务即产生重复副作用。仅事后记录请求、回执和会话结束检查点不能覆盖该窗口。
- **证据**：方案第 27 行要求记录可用标识、请求与回执，没有明确调用前的持久在途记录；第 26 行围绕正常交接检查点，不保证突然中断前已登记外部意图。任务状态需独立于执行会话，正是用户要求会话可释放的前提。
- **最小修正**：对需跨会话恢复的外部副作用，调用前先持久记录动作意图、目标、现有授权依据、候选/资源身份、可用操作标识及在途状态，再发起动作；事后补成功/失败/未知与回执。恢复时把未取得确定结果的在途动作视为未知并对账。平台支持幂等身份时按其能力使用；不支持查询或安全重试时只暂停依赖该结果的动作，保留不确定性。不能把这种记录宣称为外部 exactly-once，也不要求普通只读查询全部走同样日志流程。

## 非阻断的成文建议

### IPR-N1：把集成产物、登记和共享记录的实际写入者列为资源责任

- **定位**：第 17、19—20、25—26、28 行。
- **触发条件**：两席分别修改实现和测试，随后需要 rebase/merge、更新保护登记、合并报告或维护共享 PROGRESS；协调者以“只是整合/记录”为由直接写入受验收候选，或者恢复后没有人明确拥有该写面。
- **影响**：现方案已有“一资源一写入者”和交接规则，但没有明确集成产物与控制记录同样需要归属；可能使协调者重新成为实质实现者，或让不同席位同时改共享文件。
- **最小修正**：允许协调者维护其拥有的编排记录；目标产物的集成/冲突修复交给已登记的实施职责，涉及测试语义交测试职责。登记、保护配置、候选产物、共享记录都纳入实际资源表。可由现有合格席位承担，无需新增固定“集成席”。

### IPR-N2：会话边界应当产生实际换新，避免每次“评估后继续”

- **定位**：第 26 行。
- **触发条件**：每个阶段末都评估换新，但总以尚能继续为理由保留同一会话，并不断扩大阶段范围。
- **影响**：文字上符合“评估”，实质仍可能无限压缩，与用户要求释放会话不符。方案首句“按边界换新”与后文“评估换新”需要统一操作含义。
- **最小修正**：编排任务按有终点的工作包设置换新边界，到边界执行换新；确需短期延续时记录原因和下一个有限边界，不以无限扩展工作包规避。强制恢复触发条件继续保留；无须固定 token 比例、统一轮数或压缩次数。交接确认应包含实际运行 ID、资源归属和不能停止时的宿主限制。

### IPR-N3：非 coding 任务的职责用产物与核验来表达，独立性按适用边界保持

- **定位**：第 17—18、22、27 行。
- **触发条件**：编排一个研究、文档或数据任务，没有代码和单元测试，执行者因此认为实施/测试/审查分离全部不适用；或者反过来为每个简单文字修改硬凑三席。
- **影响**：前者会丢失作者与独立判断的边界，后者破坏轻量化。
- **最小修正**：在术语中将“实施”定义为生成或修改目标产物；按任务设核验方法，只有实际需要独立验收设计/测试作者时启用该职责；编排模式中的协调者不兼任相应目标产物的作者或独立审查者。简单任务继续适用直接处理，不因非 coding 扩张而新增一套流程。

### IPR-N4：经验修正规则不要形成每次变更都需额外席位的通用审批

- **定位**：第 28 行。
- **触发条件**：“独立核验收益/成本和授权后再修规则”被逐字用于拼写修复、澄清描述、无语义变化的维护。
- **影响**：经验维护会重新引入无差别独立 review 和授权门槛，与 W10 以及本方案轻量化目标相冲突。
- **最小修正**：把独立核验用于实质规则升级和其证据/收益判断；形式维护按既有授权处理。正式规则职责、验收或授权发生变化时才适用对应用户决定，不另设统一席位和确认要求。

## 应保留的设计

- 简单任务可完全不启用 lane、计划目录或完整编排；需要短时独立测试不等于升级为大任务。
- 编排模式下协调者不实现、不写验收测试、不做相应候选代码审查；独立审查可兼任确认，避免固定多一席。
- 独立性依实际实例、角色、候选和写入历史判断，不能用厂商不同或更强模型替代。
- 新测试证据可用、独立确认、纳入保护和修改正式验收分开；既有回归基线与新测试 TDD 红起点分开。
- 真实资源版本、字节及实际环境优先于 HEAD/tree/status；隐藏索引标志、忽略输入和外部输入都按实际影响处理。
- 实际宿主控制与文档承诺分开；事后检测不是事前阻止，保护不足不能自行降低既定验收。
- 不安全的 import/package 归一化和“路径不相交即无冲突”的推断不再作为通用证明。
- 原始起点与集成起点分开；候选变化使受影响证据失效，恢复不清零尝试与成本。
- 原会话实际停止、写入归属接手、迟到结果和宿主能力限制分别记录；归档聊天不等于结束运行。
- 外部动作遵循既有授权，未知不记成功；经验不按固定 Seen 次数自动升级规则。
