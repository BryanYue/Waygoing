# 通用 Agent 工作与编排规格 v2.10 候选

状态：候选规范，尚未替换现行全局规则。适用于代码、配置、数据、研究、文档和外部事务；可由单一工具或多个工具执行。
定位：作为 Orchestration Protocol v2.9 的通用化替代候选，吸收 W01–W12 的适用原则。正文自包含，不要求另一工具能够读取 Codex 的全局文件。本候选不改变现有全局文件和加载路径；采用布局另按既有要求明确。
核心流程：明确目标与完成条件 → 按需选择执行方式 → 完成工作 → 核验实际结果 → 交付并结束当前执行责任。

使用入口：日常任务直接处理并必要验证；需要新验收测试时增加独立测试作者；需要多方协调或长期恢复时再启用编排角色、持久状态和换新流程。后文的条件规则只在适用场景启用，不要求每个任务生成全部工件。

## 0 适用范围与要求来源

**G01 要求优先。** 遵守运行环境的上级指令和权限边界。当前用户明确要求优先于通用默认；项目正式约定决定具体验收。助手假设、摘要、进度记录、模型意见和经验条目不能自行改变正式要求。冲突须核对来源及授权，只暂停依赖该冲突的工作。

**G02 按任务启用编排。** 简单、边界明确的任务直接处理，不强制 lane、计划目录、worktree、独立收官席或固定数量代理。主代理在这种任务中可以是实施者。需要并行写入、跨职责依赖、长时恢复或分阶段验收时启用编排。仓库大小、文件数量、任务名称和 FEATURE 标签不是自动启用条件。

lane 是编排任务中有独立目标、写入范围、依赖和完成条件的工作流，不是每次修改的固定包装。阶段、波次按需设置，不保留无作用的层级。小任务需要新增验收测试时，也可单独委派测试作者，无须因此建立 lane。

**G03 授权内持续推进。** 用户已授权的工作持续完成。模型、思考档、拆分、命令和计划形式按需要调整；不能据此削减正式验收。只有拟改变尚未获准变更的正式需求/验收、指定基线、关键职责或行为契约，超出授权范围，或缺少无法自行查明的必要用户决定时，才请求额外确认。先说明问题、证据、拟变更、影响和回滚边界。沉默不构成授权；继续不依赖该决定的已授权工作。

## 1 角色与独立性

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| 用户（Boss）或其明确授权的人类负责人 | 确认目标、正式约束和需要其决定的变更 | 授权须能回溯至原始指令及适用范围；协调者不能自认此角色 |
| 协调者 | 拆分、派发、登记、调度、核对身份与证据完整性、执行有效裁决 | 不实施业务产物，不编写验收测试，不做代码/产物语义审查，不自行降级技术 finding |
| 实施席 | 完成代码或其他目标产物，诊断并修复实现缺陷 | 只能写约定范围；可质疑测试或核验方法，不能自行改正式判据或宣布通过 |
| 测试/验证设计席 | 根据需求设计场景、编写验收测试或核验方法，解释结果 | 独立于对应实现作者；发现假设错误须依据原始要求纠正 |
| 独立审查/确认席 | 核对实现、测试/核验方法及实际证据，判断目标是否达成 | 不参与该候选的实现和验收测试编写；可兼任收官确认 |

**G04 按实际责任认定独立性。** 角色不绑定 Codex、Claude 或其他厂商。使用不同实例和明确写入范围；同一实例改角色名称、使用更强模型或多模型一致，不构成独立核验。审查输入应有原始要求、相关完整产物、版本与原始证据，不必继承作者全部推理历史。

协调者可提出异议并安排原审查席重核，但不能自行改变技术问题的性质、阻断性或有效验收结论。原审查席可依据新证据纠正事实错误并留痕；实质分歧仍未解决时，最终独立裁定者不应是该 finding 作者、实现者或测试作者。可复用现有合格席位，不预设额外常驻席位。修改正式要求仍按 G03。独立审查可以在隔离环境执行验证；只读表示不改被审候选，不表示只能读文本。无法独立审查时如实说明，仅暂停必须依赖它的验收。

简单任务升级为编排时，登记主代理已经完成的改动及作者身份。主代理可以转为协调者，但停止相应实施，不审查或确认自己此前的候选；原有产物交独立席核验，后续实施写入明确交接。

**G05 席位和模型按需要配置。** 测试和实现作者分开；实施者可运行现有测试或做临时诊断，不能用自编诊断替代独立验收测试。非代码任务按风险安排独立核验，不强制每个任务设置全部角色。不普遍增加第四个收官席，不要求审查模型档位高于协调者。复杂协调任务优先考虑具有相应推理和上下文能力的模型，但不把高档模型设为所有任务的固定门槛。型号与思考档分别选择，记录实际路由；能力未知或回退时说明事实。

## 2 任务约定与持久状态

**G06 修改前明确必要约定。** 编排任务至少明确：原始要求入口、目标与非目标、基线和实际输入、允许资源/文件、行为不变量、必需场景与检查方式、职责与依赖、停止条件、回滚边界。未知项先调查，尚未查实的原因标为假设。简单任务可以用几句话表达，无须新建固定文件。

正式约束与可调整执行方法分开。沿用既有 delta、dispatch 等布局时，前者保存正式目标/验收，后者保存派发和执行方法；更新方法不改变正式约束。非 Git 任务不强制 task 分支或提交。

**G07 一个任务保留一个进度入口。** 按项目+任务隔离，沿用现有记录。需要恢复的任务至少能找到：
- 稳定任务标识、规格版本、原始要求和有效授权入口。
- 原始基线、当前候选/产物身份、实际输入及工作目录。
- 当前责任人与资源写入者、实例/运行标识、仍在运行的任务。
- 已完成和未完成、验证及未覆盖项、关键决定和原因、已否定方案、阻塞与下一步。
- 在途外部动作、已知回执、结果未知项和恢复入口。

在用户纠正、关键决定、阶段成果、责任转移时增量更新；不每轮重写全文。大日志和细节产物通过引用保存。状态记录不是正式要求的替代来源，修改状态不能改变验收。

## 3 写入归属与工作区

**G08 开工预登记实际工作区。** 开工时登记计划中已知且拟使用的全部 worktree、沙箱或其他独立工作区，包含真实路径/资源标识、来源基线、当前候选、负责人、允许写面、保护状态与相关运行标识，并核对实际状态。后续新增工作区在首次写入前补登记，无须预建所有可能用到的工作区。登记属于授权内执行，不自动增加用户批准。

保留原有脏内容、历史和其他写入者成果；不得擅自 stash、清理、替换基线或用干净 HEAD 代替用户指定输入。依赖未提交内容或外部资源时，明确纳入候选并标识其版本。

**G09 同一资源同一时段只有一个写入者。** 实现与测试分别拥有明确写面；共享配置、集成产物和进度记录也要指定写入者。可独立验证且写面不重叠的工作可以并行；目录迁移、共享生成物、环境与语义依赖仍需协调。只读席不强制 worktree；需要执行验证时可使用隔离环境。

接手前确认原写入者已停止，或其相应写权限已实际撤销。无法确认时，新实例只做只读恢复和调查，不开始同范围写入。写面声明和事后 diff 只是约定/检测，不能宣称已经提供宿主权限隔离。

## 4 正式判据、检查与证据

**G10 正式判据受来源保护。** 用户明确要求、正式契约、指定基线、已确认计划的业务约束及既有验收/golden/阈值，不得为当前实现通过而降低或替换。禁止删失败样本、缩小必需覆盖、放宽阈值、迎合实现改预期、绕开真实入口或改写结果。

未确认且未纳入正式验收的助手假设或测试预期，可以依据原始来源纠正并说明原因；不能把既有验收重新标为临时假设。新增回归测试、补证据及不改变验收语义的维护按授权正常推进。

**G11 保护方式不能改变授权语义。** 保护集用于限制正式判据写入；监视集用于发现与业务改动同处一个文件的验收配置变化。正式阈值、选择规则与证据生成约束，无论放在哪个集合或外部资源中，都保持正式保护。监视到变化须独立判断；未经授权改变受保护语义时阻断相关验收。

按任务要求记录实际可用的权限、工具入口限制、结果核验和授权更新机制及覆盖范围。原件字节/资源版本核对、索引状态或忽略输入检查按适配执行；不把 Git 显示干净、单个探针被拒或事后恢复当作全程保护的证明。必需保护缺失只暂停依赖它的工作，不能以记债务代替。

授权变更仅纳入获准差异，同步更新登记、实际保护覆盖和验收引用；按已有授权落实时不重复批准。授权引用字段存在，不自动证明授权真实或足够。

**G12 保留最小验收追溯。** 每项正式要求或必需场景，能追溯至适用检查/观察方法、对应候选与执行凭证、结论及未覆盖项。自动测试、人工审阅、真实设备、外部回执按任务适用选择。必需项和执行状态须可核对；机器可判定且适配已支持的部分用检查器完成。已启用或正式要求独立审查时，由独立席判断方法是否足以支持结论，并确认变更必需检查的选择、范围或替代方法后覆盖仍然满足；其他任务由当前责任人核对并留证。绿色结果数量不替代覆盖判断；无法确认的项保持未验证。已经明确的等价执行参数调整不另设审批。

**G13 证据绑定实际候选。** 检查记录至少包括相关输入/产物身份、命令或操作、必要环境和配置、执行者/时间、结果、必要日志/输出引用，以及缓存或历史证据来源。仅提交号、tree hash、时间戳或状态干净不足以证明所有实际输入一致。

已有报告、台账和其他代理的完成声明只是定位入口；核验关键结论时检查当前候选的实际产物和必要原始证据。结果区分通过、失败、未执行、环境阻塞、结果未知、已失效。缓存或旧结果仅在输入、配置、环境和适用条件仍成立时复用，标明来源；不能冒充本次真机或外部操作证据。候选实质变化使受影响证据失效，审查确认可复用范围；不机械重跑无关检查。

## 5 独立测试与产物核验

**G14 验收测试由独立作者负责。** 测试/验证设计席从正式要求提取前置条件、操作、预期与边界。实施席可核对理解并提出异议；修改测试由其当前作者处理，正式验收语义变化按 G03。审查/确认席同时检查实现、测试设计与实际结果。

测试可以成为有效证据、通过独立确认、纳入正式保护登记；这三件事分别记录，不把全部新增测试都变成等待用户逐条批准的事项。独立确认不能自行增加用户正式需求。

**G15 解释失败，而不只记录红绿。** 新测试或有明确共同原因的一组测试，记录：测什么、要求来源、对应基线/候选、命令/环境、预期与实际结果、失败类别、原始证据及后续处理。类别至少能区分实现缺陷、测试假设问题、环境问题、未执行和原因未明。

回归证据应尽量证明旧故障被捕获、修复后通过。编译失败、环境错误、跳过或测试自身错误不能冒充目标行为失败。全新接口在旧版本不存在时说明这一边界，并补充有意义的行为核验；原本就通过的测试可以补充覆盖，但不能冒充修复证据。

**G16 分开三类基准。** 已有验收的基准结果、新测试的预期失败证据、当前候选的最终结果分别记录。允许独立测试先提交形成合法的红色实现起点，不要求这个起点同时拥有相同完整闸的通过凭证。

测试名称、数量、跳过情况和配置变化是审查信号。测试重组、参数化或跨模块迁移须说明场景映射；不能只看名称相同/数量不减，也不把任何删除或改名自动升级为新用户决定。

## 6 问题处理、集成与回退

**G17 问题有身份、证据和结论。** 需跟踪的 finding 记录稳定标识、候选/版本、触发条件与证据、性质、阻断性、范围、处理者和关闭依据。范围外问题只改变路由，不自动取消其对当前验收的影响。已登记且可能影响当前验收的问题尚未完成分类时，先不放行相关验收；纯线索与未证实怀疑单独标注，不能冒充已成立缺陷。关闭可为修复并验证、证据支持的误报、关联有效问题的重复、明确原因的失效；不能通过重命名问题或候选逃避处理。行为/契约问题关闭前检查受影响机制的同类路径，记录搜索或核验范围、命中与处置；按实际风险确定范围，不机械穷举无关代码或资源。

债务记录责任与期限，不把未满足的验收变成通过。已知红有明确适用范围和期限，新增豁免按 G03，已关闭问题重现不得默用旧豁免。拒写事件保留实际可观测的上下文和来源，复核原因，不自动认定恶意，也不隐去真实越权尝试。

**G18 修复以信息增量为前提。** 编排时在执行计划中给出适合任务的尝试/预算与停止条件；材料不足先补材料。失败先判断原因，每轮说明新增证据与变化；同一问题没有信息增量即停止重复补丁/测试，重审假设或报告缺口，继续无关工作。

更换实例、模型或拆分 lane 不清零同一问题的尝试和成本。另派时移交有效成果，不默认从头重做；达到约定停止条件后选择有依据的回退、隔离或待决定，不自行无限续期。

**G19 集成结果重新绑定证据。** 原始任务基线保留不变；集成基线和当前候选另记。按项目策略 merge、rebase 或其他合成，不以路径不相交保证无冲突，也不把冲突直接认定为派发错误。无冲突的机械合成可由协调者触发并记录实际写入归属；语义冲突由相应实施者或测试作者处理，协调者负责调度；实质修改后重新核验受影响范围。

回退前确认实际变更归属、依赖和恢复边界，保留原有输入、其他写入者成果及必要证据。不默认重置共享分支或清空工作区；归属不明先隔离候选，不能以回退清理不属于本任务的内容。

## 7 会话检查点与换新

**G20 任务持续，会话有边界。** 每个长任务执行实例领取有限工作包，明确完成条件、检查点与停止条件。阶段完成且没有必须保留的在途责任时，后续阶段默认由新的执行上下文接手；协调者运行也适用。确需短期继续同一实例，须记录具体依赖/收益和下一个有限收口点，到点执行交接，不得只重复改写理由而无限延期。简单任务不套用阶段仪式。

独立审查使用独立上下文。出现持续遗忘约束、重复无效返工、下一步错位或恢复不可靠时，先回读原始依据校正；仍不能可靠继续就停止相关写入并交接。保留原生压缩，不以统一 token 比例或固定压缩次数替代任务边界。resume、继承历史的 fork、压缩都不能登记为干净换新。

**G21 交接顺序明确。**
1. 停止扩大派发，核对正在运行的实例、写入者、在途动作及当前候选。
2. 在同一任务记录保存检查点：要求与授权入口、实际输入/产物、有效与失效证据、决定及原因、未完成项和恢复动作。
3. 确认旧写入者停止或权限撤销；仍继续的任务须有明确且不冲突的归属、结果回收入口。将最后结果和状态变化补入检查点。
4. 通过当前授权及宿主允许的方式启动新上下文，回读适用规则、原始要求与任务记录，核对真实产物、分支/资源版本和运行状态。
5. 记录新实例接手的候选、范围与运行身份；确认当前责任唯一后才开始写入。旧运行迟到的结果作为待核对证据，不直接覆盖状态或恢复写权限。
6. 实际结束旧实例不再需要的运行责任，保留历史和证据。记录终止/释放的实际结果。

无法确认相应旧写入已停止或写权限已实际撤销时，新实例仅对同一写面做只读恢复。宿主不能新建、停止或释放时，记录具体能力缺口和安全的人工接续步骤，不能把归档聊天声称为终止运行。交接不是只复制一段摘要，也不承诺完全无损。

## 8 外部动作与非代码任务

**G22 外部效果按授权和实际回执处理。** 发送、发布、预约、支付或修改外部资源，遵守当前任务的明确授权和宿主权限；审查通过不自行产生这些动作的授权。先生成可审阅产物，必要确认发生在产生外部效果之前；已有授权不重复索取。

需要跨中断恢复的外部动作，在调用前持久记录操作意图、目标、授权依据、候选/请求摘要、操作标识及在途状态；调用后补充外部回执与实际状态。结果未知时先查询对账；只有确认未执行或具备可靠幂等条件时才重试。无法确认就保留未知并停下该动作，其他无依赖工作继续。本地记录不保证外部 exactly-once。

**G23 用领域证据定义完成。** 研究任务保留来源与结论关系、日期及不确定性；文档/设计任务核对实际产物、内容和呈现；数据任务保留输入版本、转换及核验；外部事务核对目标资源与回执。无需为这些任务虚设 Git、单元测试或软件发布流程。

产物生成、工具成功、功能验证、外部生效和人类验收是不同状态。交付采用与任务完成条件相符的证据，不把其中一层自动提升为另一层。

## 9 收官与经验更新

**G24 满足完成条件后交付。** 收官核对要求与实际产物、相关职责/不变量、必需检查、未完成项、债务和授权变更。编排任务由符合独立性要求的审查/确认席形成结论；协调者核对身份与完整性并原样保留结论，异议另记。没有已知阻断且必要验收满足即交付，非阻断不确定性如实说明，不无限扩测。

交付说明结果、证据对应版本、正式判据的语义变更及授权、未验证范围、遗留责任，以及仍运行或需要接续的任务。编排任务汇总协调者对必需检查方法、分类/路由、审查安排及适用收官项的实质调整和依据；没有则说明无。面向用户的说明按读者需要组织；机器记录和代理交接无需强制套用报告格式。

**G25 经验服务于后续任务。** 有价值的经验附事件/证据、适用范围与原因，可记成功实践。需要跨任务复用时，沿用项目已有的经验/设计记录，任务进度引用它；开工按当前任务检索相关经验，不强制每次通读一本全量错题本，也不自动写入全局工具记忆。重复发生提高复核优先级，不自动升级为全局强制规则。规则修订记录来源、影响和试用状态；涉及正式约束变化按 G03，普通澄清不固定增加审批或席位。未实跑可如实标注，不禁止修正已证实的规格错误。

## 10 按需读取的适配要求

| 适配范围 | 必须明确的事实或项目约定 |
| --- | --- |
| Codex、Claude 或其他运行宿主 | 实际模型/档位、可用工具与权限、独立实例/新上下文创建方式、状态查询、停止/释放与结果回收能力；不可用能力不得宣称生效 |
| 跨产品插件 | 原始要求与输入、角色与写入归属、实际调用状态、证据和回传结论；插件不是通用协议的必经层 |
| Git/代码项目 | 原始基线、实际未提交输入、候选和集成基线、写面、保护清单、检查命令/环境、集成与回退策略 |
| 无 Git 的资源 | 可定位的资源身份、版本/快照、写入者、允许操作、核验与恢复方式 |
| 外部服务 | 当前授权、目标身份、操作记录、查询回执/幂等能力及结果未知时的处理 |
| 必需硬隔离不可用 | 明确缺失范围，只暂停依赖该保护的工作；经原有授权允许的方式可继续，不自创降级授权 |

代码项目可继续使用 MOVE/EDIT/FEATURE 分类，但它们不是通用风险等级或人工批准等级。严格纯搬迁需验证内容与路径对应及入口/资源影响；不能一律忽略 import、package、空白或文本替换来证明行为不变。类型误判应根据事实修正，降低已确认验收仍按 G03。

下游消费方必须实际解析到本次候选产物的版本/哈希或等价身份。在线刷新失败时，只有身份可核对一致的离线证据才能支持结论；对不上记下游验证未完成。提交消息格式、公司 dev-workflow、具体构建和设备命令放项目适配，不设为通用规格。

沿用 v2.9 的代码项目，默认保留 task 到受保护基线的人工合并点；自动合并须有明确适用授权，不由协调者自授。新规范中的“按项目集成”不自动改变该边界。

## 11 采用与验证

本候选本身不证明权限、检查脚本、会话关闭或外部恢复机制已经实现。规则正文定义目标行为；适配和脚本只负责其可执行部分，判断项须有明确责任与证据。

采用时核对两端实际加载入口，发布并记录所用版本；W01–W12 保留适用的客户端路由与通用底线，冲突职责和引用须同步处理。共享层或现有两文件的接入布局由采用时明确，本候选不默认创建新全局规则源。运行中任务继续使用已确认版本；如需迁移，明确差异和适用授权后再切换。

试点至少覆盖：小任务不建 lane；有独立测试作者的行为改动；已有验收基准与新测试预期红分开；真实输入与缓存身份；目录搬迁冲突；新旧实例写入交接及迟到结果；外部效果结果未知；非代码产物核验。单用 Codex、单用 Claude 各至少完成一个适用完整流程，不要求测试所有组合。记录实际通过、未执行和能力缺口，据此决定后续脚本与自有 harness 范围。
