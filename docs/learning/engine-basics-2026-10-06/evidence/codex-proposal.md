# Codex 首轮教学提案

日期：2026-10-06。这是讨论输入，不是已批准的 Engine 架构。

基线 fdd0b1e851a99036cac7e07f489cc2d56b85956f，当前仓库仅 README 标题。用户是有 API 开发经验的领域初学者。主代理统一写文档，Claude 只读评议。

拟定路线：
1. 用虚构订单退款 API 的需求变更建立一次调用：参数和 token、输入消息、生成输出、训练参数与当前输入的差别。可在纸面完成，不安装模型、不调用收费 API。
2. 工具 schema、宿主执行、工具结果回填与循环；用读文件成功和超时两个轨迹区别调用、执行、验证。Agent 与固定 workflow 为工程上的可用区分，不当作全行业唯一术语定义。
3. 上下文选择：目标、约束、源文件、证据、历史；容量不等于有效使用，摘要可丢失条件。先让学生做小型人工选择，再读长上下文材料。
4. 检索：从关键词、符号定位、语义检索到过滤和重排；之后再读 RAG 原始论文的流程、实验和局限。检索召回与生成准确性分开。
5. 记忆：存储、选择、写入、更新与失效；区分会话状态、任务进展、事实与推测，不等同向量数据库或模型重新训练。
6. 关系：先做纸面有向边，再看 Aider repo map；能通过关键词解决的问题不强加图。知识图谱、代码依赖图、执行图不同。GraphRAG 作为选读。
7. 需求变化：记录来源、版本、生效条件、被替代关系，讨论增量更新的漏边与摘要残留；Graphiti/Zep 作为可复用实现候选而非已定依赖。
8. 小型迁移与评估：同一任务比较按需搜索、检索＋笔记、关系地图；保持任务信息与预算说明，观测过期信息引用、交接后的正确行动、维护成本。不执行历史实验。

预计主线约 20–30 小时分散学习，先只提供第一课完整教材（60–90 分钟拆为短段），后续阶段提供明确读哪部分、练什么、通过什么表现进入下一步；估时随实际反馈调整。主线外部阅读先限少量摘读，选学/深入不得暗中作为前置。
