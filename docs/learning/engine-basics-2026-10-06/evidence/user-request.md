# 用户原始要求

记录日期：2026-10-06。以下为本次教学任务原话；用于保持范围，不代表旧实验恢复授权。

Engine 学习资料与渐进教学计划
请在当前 Engine 本地项目中，为我设计一份可以实际跟学的学习资料与教学计划，并使用已安装的 Claude Code 插件与 Codex 共同讨论。双方可以提出不同教学路线、质疑安排，检查技术解释和资料依据，保留有意义的分歧及理由。请实际调用插件；如果调用失败，说明具体问题，不把单模型结果说成双模型讨论。
我的起点：有软件工程、API 开发与 AI 应用使用经验，但没有系统学习过大模型与 Agent 的底层机制，对上下文工程、记忆、检索、知识图谱等原理了解很少，也很少读论文。请把我当作这些领域的初学学生，考虑理解和吸收负担。
我的研究背景：希望探索一种可复用的外接机制，让 Agent 在连续工程工作、需求变化和任务交接中，获得当前有效的项目理解，减少重复摸索和过期信息误导。先从 coding 项目开始，再考虑通用 Agent。持续更新的项目地图是一个初步构想：关联目标、业务、架构、代码、决策和进展，变化后维护相关理解；它不是已确定的唯一架构。我希望复用已有研究与开源组件，而不是所有部分从零造。
请自行设计由浅入深的教学路径。先用熟悉的工程例子建立模型输入输出、上下文、工具调用和 Agent 执行机制的基础，再适时深入信息管理、检索、记忆、图及变化后的更新。论文和复杂源码安排在对应基础建立之后，不一开始堆名词、公式和链接，也不要求重学训练模型所需的全部数学。
选择少而精的主线材料，区分必学、选学和深入阅读。说明为什么这样排序、前置知识、具体怎样学、学完能解释或判断什么。教我如何读论文的问题、方法、假设、实验和局限，用少量复述或迁移练习了解吸收情况并调整速度；给学习负担估计，不承诺固定天数吃透。
资料以原始论文、官方文档和实际开源实现为主，标明来源和日期。结合我的愿景说明各方法解决哪一部分、在什么条件下有效、怎样与其他部分结合、尚有哪些缺口。不要把论文中的局部效果当成整个方案已被证明。
请将学习计划和配套资料保存到当前项目合适的文档位置，并在活动中给我简明导读。可以先给可学习的第一部分，再逐步完善，不必等成一套百科。此次只做学习资料、教学设计和讨论，不修改业务实现、不恢复旧实验。保留现有文件，合理控制本地资源，Claude 重型工作串行执行。
