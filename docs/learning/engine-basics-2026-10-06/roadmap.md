# 路线与学习节奏

这条路线围绕“现在该给 Agent 什么信息”展开。先学信息如何到达模型，再学怎样找到和维护它，最后比较是否值得加入关系图。每阶段估时包含例子、指定片段和短练习，均为待学生反馈校准的规划值。

## 路线总览

| 阶段 | 先修 | 学习与练习负担 | 学完能判断什么 |
|---|---|---|---|
| 1 一次模型调用 | JSON、API 请求响应 | 1–1.5 小时 | 文件存在、历史保存与本次模型能看见有何不同 |
| 2 工具与执行循环 | 阶段 1 | 1.5–2 小时 | 调用、执行、观察、验证分别由谁负责 |
| 3 有效上下文与第一篇论文 | 阶段 2 | 3–5 小时 | 信息是否相关、足够、有效；论文结论的边界在哪里 |
| 4 找到需要的信息 | 阶段 3 | 2–4 小时 | 关键词、符号、语义和结构索引各适合什么问题 |
| 5 记忆的写入与读取 | 阶段 4 | 2–3 小时 | 什么应跨会话保留，什么必须重新查证 |
| 6 变化与任务交接 | 阶段 5 | 2–3 小时 | 旧规则、派生摘要与进展怎样失效，接手者还缺什么 |
| 7 关系与图的必要性 | 阶段 6 | 3–5 小时 | 哪些查询因关系受益，维护关系是否值得 |
| 8 迁移与比较方法 | 阶段 1–7 | 2–3 小时 | 外接机制在哪些条件下有用，哪些部分仍未验证 |

合计约 17–27 小时；第一部分教材横跨阶段 1 和阶段 2 的入门段，重复读到的内容不重复计时。选学每次只挑一项，通常多 20–75 分钟；深入论文或源码每项约 1–3 小时甚至更久，不计入主线。无固定完成天数。

## 阶段 1 一次调用

读 [第一部分](01-model-and-agent.md) 至“第一次停下来”。用退款 API 对照权重、请求参数、token、上下文四个概念。把“R2 在磁盘”“R2 存在聊天数据库”“R2 进入本次输入”画成三个方框，补上中间需要的软件动作。

练习 E1：用五句话解释为什么一个新会话可能继续用旧规则；迁移到鉴权 API。误解判断：“只要仓库有最新文档，模型就知道。”能反驳这句话即可进入下一阶段。基础补充按需读 [Hugging Face 选学](sources.md)，不学训练部署。

## 阶段 2 工具与循环

继续第一部分后半段，读来源 S1 的一次 client tool 往返，再读 S2 的 Agent 与 workflow 区分。对 [练习 E2](workbook.md) 的六步轨迹标出模型、应用、工具三个角色，再把成功结果替换为超时。

必须能复述“生成工具请求之后，文件还没有被读取”。迁移练习是：把读文件替换成执行测试，解释为何退出码、版本和测试覆盖都影响完成判断。误解判断：“模型输出了一个测试命令，所以测试通过了。”本阶段不要求搭框架。

## 阶段 3 上下文的选择与有效性

先做 [E3](workbook.md)：在有限卡片名额中选给接手者的信息。首次只关注任务和证据；第二遍给留下的事实补“来源、观察时间、生效条件、被替代情况”。这是一套教学用记录方法，不是 Engine 数据模型定案。

接着读 S3 指定片段，比较原文、摘要与文件入口。再按 [论文阅读卡](paper-reading.md) 阅读 S4《Lost in the Middle》。选择它作第一篇，是因为实验变量直观，容易练习“改变什么、测了什么、还没证明什么”。

检查：五句话说明“更多上下文”可能同时增加覆盖与干扰；把论文实验迁移为一个需求文档顺序对照设想；判断“论文发现中间位置较差，所以所有重要材料永远放最后”哪里越界。不需要复现论文或学其全部模型架构。

## 阶段 4 检索

先不装向量数据库。用 E4 的三个查询查同一套卡片，比较：精确词/符号匹配，按意思找相近片段，利用结构定位文件。embedding 可先理解成将内容表示为一组数，检索使用这些表示的相近程度；相近程度不是事实真假的分数。

用一条工作链解释过程：组织资料与来源 → 提出查询 → 找候选 → 按版本/范围过滤 → 需要时重新排序 → 选入上下文。过滤也可以在检索前进行，具体次序要看系统；重排通常只重排候选，救不了根本未找到的资料。

读 S7 的 Aider 文档，观察代码结构如何帮助选择上下文。此处只读输入输出示例，把图排序源码留到阶段 7 之后。RAG 原论文是选学，先通过自己的例子理解“取资料后生成”。

检查：说出关键词优于语义检索的一个场景，及相反场景；解释为什么“检索命中旧规则”不算取到了当前答案。迁移到一次你熟悉的接口改名。没有一种检索方式被预先宣布胜出。

## 阶段 5 记忆

做 E5：给陌生接手者留下不超过五条笔记，分别考虑稳定规则、任务进展、临时假设、失败尝试。每条写清何时需要回源复核。读取当前文件属于取证；从外部记忆选回材料属于记忆读取，两者可以组合。

用熟悉的缓存类比：落盘解决保留，查询解决找回，缓存键/版本解决部分失效；但业务决策是否仍适用通常不能只看文件 mtime。摘要是派生资料，可能丢掉“仅普通商品”等条件。

检查：用五句话区分模型权重、当前上下文、服务端保存的会话状态、跨会话笔记；迁移到一个失败调试记录；判断“向量数据库就是 Agent 的全部记忆”为什么不成立。需要框架实例时选读 S6，MemGPT 留到还想理解分层记忆时。

## 阶段 6 变化与交接

现在打开 E6 的变更卡，更新你刚写的笔记。先使用扁平表和手工检查：新增资料、确认适用范围、标记被替代内容、检查派生摘要、返回相关源文件、列出待验证项。保留历史不意味着把旧规则继续作为当前规则送入上下文。

重点区分两个时间：“什么时候得知”和“什么时候生效”。更晚写入的意见不自动覆盖较早批准的要求；新需求也不表示代码已改完。新版本要求获批不自动改变当前任务目标，应分别记录版本范围和目标是否切换。工具读取成功和部署生效仍是不同事实。

检查：交接者只看你的包，能否知道现在该做什么、不该声称什么、哪里有冲突？写一个三句话交接包，并说明遗漏风险。若扁平笔记已足够，就如实记录；不故意制造它必须失败的结果。

## 阶段 7 关系与图

先做 E7：把“规则适用于商品类型”“代码实现规则”“测试验证行为”“摘要来自原文”画为有方向、有类型的边。图是表示关系的方法，关系表也可以存它，不等于必须引入专用图数据库。

区分三种图：代码符号/依赖图、业务事实知识图、程序执行流程图。它们服务不同查询；Aider repo map 不能自动提供业务批准关系，LangGraph 的执行图也不等于业务知识图。

把“修改规则会影响哪些已知记录”作为查询，沿明确的边找候选，再回源验证。漏抽一条边仍可能漏改，关系维护、实体对齐和权限都需要成本。图提供候选影响范围，不自动证明因果或完整性。

检查：给每条边说明来源；画出一个可能漏掉的影响；比较扁平表与图各要维护什么。如果兴趣仍在，深入材料二选一：跨文档整体主题看 D1 GraphRAG；时间事实和更新看 D2 Zep/Graphiti。不要同一阶段同时啃两套系统。

## 阶段 8 迁移与比较

按 E8 写一页研究草案，不运行旧实验。选择一个你熟悉的 coding 任务，再选择一个非 coding 的规则变更例子，区分共同机制与代码专属连接器。

候选可为：按需搜索＋简短交接；检索＋有来源的笔记；关系索引＋增量更新。先共享同一组原始信息、任务时点和正确判断依据，再说明各自上下文、调用与维护预算。所有候选都要能取到新资料，不能只让图方案独享更新。

从阶段 3 起持续使用的三个问题此时变成评价维度：是否用了过期资料；交接后的下一步是否正确；为此付出多少维护/检索成本。额外记录证据覆盖、遗漏与端到端任务结果，不只比较答案“看起来更全”。复杂方案若没有额外收益，简单方案可以胜出。

## 方法与 Engine 愿景的对应关系

下表是在你研究愿景上的教学映射，属于待验证的设计推理；来源支持相应局部机制，组合起来的整体效果仍需验证。

| 愿景中的需要 | 可复用的方法或入口 | 有效条件与组合方式 | 仍有缺口 |
|---|---|---|---|
| 知道该看哪些代码 | 按需搜索、Aider repo map（S7） | 用符号和结构缩小范围，再读取原文件 | 动态调用、业务动机、未记录的决策 |
| 找到分散的解释 | 关键词/语义检索、RAG 思路（S5） | 文本覆盖充分，保留来源；配合范围与版本过滤 | 召回遗漏、旧资料高相似、生成误读 |
| 接续任务 | 有来源笔记、会话持久化（S6、MemGPT 选学） | 记清目标、已做与待做，接手时回源查关键状态 | 摘要丢条件，历史完成不代表现状未变 |
| 连接目标与实现 | 类型化关系表或图；D1/D2 仅作候选 | 关系有证据、实体可对齐；检索出关联材料再验证 | 自动抽取错误、漏边、关系维护成本 |
| 处理变化 | 版本/适用范围、失效记录、派生物检查；Graphiti（D2） | 新信息到达后能识别影响，源与摘要有对应关系 | 未通知的变更、冲突权威不明、摘要没同步 |
| 接到不同 Agent | 文件/查询 API，之后可看 MCP 选学 | 每个宿主实际调用并注入所需材料；保留权限边界 | 接口通了也未必会用；不同工具能力和上下文策略需适配 |

一种待比较的组合是：原始来源保持可追溯 → 建立搜索或关系索引 → 按任务及有效性选择材料 → 交给宿主的执行循环 → 用实际观察更新笔记。它不要求把所有知识放进同一种数据库。当前有效的理解还包含冲突、缺口和未知，不能只返回一个看似完整的结论。

## 跟学反馈与调整

每阶段只交三样：五句话以内的复述、一道迁移题、一句误解辨析。它们是老师选择下一课的依据，不是考试分数或 Engine 验收。

| 观察到的表现 | 下一步 |
|---|---|
| 能复述并能迁移，能指出证据缺口 | 进入下一阶段；选学可以跳过 |
| 术语会说，换一个 API 就不会判断 | 再用熟悉例子练 15–30 分钟，暂缓新增阅读 |
| 混淆“保存”和“进入输入”，或“建议”和“已执行” | 回到第一部分相应一小节，教师用一条轨迹示范 |
| 英文或论文阅读负担大 | 教师先解释一幅图和一个实验变量，再回原文核对；保留不懂项 |
| 已经能主动指出方法局限 | 增加一项深入材料，不整批增加课程 |

教师每次开始先回顾上一题，再介绍最多两三个新概念；不因为一次答错重新从头教。记录实际用时及一个未解问题即可，尚未收到答案的阶段不能写成“学生已掌握”。
